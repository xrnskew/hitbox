# HitBox

HitBox — конструктор игр (веб-приложение). Название сайта и заголовок вкладки — «HitBox — конструктор
игр». Сейчас в нём три игры-урока — Корзинка (`catch`; раньше Catch и «Лови яблоки»), Птичка (`bird`, как Flappy Bird)
и Космос (`space`, стрелялка: корабль, пули, волны пришельцев):
ученик по шагам пишет игру на JavaScript, вкладки склеиваются в один скрипт и запускаются
в iframe.

- ТЗ и механизмы, которые нельзя ломать: `docs/SPEC.md`
- План и предложения: `docs/PLAN.md`; план третьей игры «Космос» — `docs/PLAN-space.md`
- Отложенные задания (шаги гайда под карту и др.) — `docs/PLAN.md`, раздел «Дальше»

## Стек

- React 19, TypeScript (strict-ish: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`)
- Vite 8, `@vitejs/plugin-react`; `npm run build` — сайт в `dist/` (base из `BASE_PATH`, по умолчанию `/`).
  Версии одним файлом (`hitbox.html`) нет и не нужно — убрана по просьбе пользователя, не возвращать
- CodeMirror 6, acorn
- Стили — обычный CSS: токены в `src/styles/tokens.css`, компоненты на CSS-модулях. Tailwind нет.
- Линтер: oxlint (`.oxlintrc.json`); формат — prettier `--print-width 120 --single-quote --no-semi`
- Алиас `@/` → `src/` (настроен в `vite.config.ts` и `tsconfig.app.json`)

## Устройство

- `src/core/` — чистые модули без DOM и React (склейка, синтаксис, переводы ошибок, прогресс,
  уровни — что открыто, хеш пароля готовой игры, рисунки: холст `pixels.ts`, сами рисунки в `art/`, набор `pictures.ts`).
  Импорты внутри — относительные с `.ts`, чтобы их можно было запускать прямо в Node:
  `node -e "import('./src/core/syntax.ts').then(m => console.log(m.findSyntaxError('if (')))"`.
- `src/lessons/<id>/` — пакет урока (`catch`, `bird`, `space`): код вкладок, тексты гайда, квесты, подсказки, кнопки
  на корпусе приставки (`controls`), цвет корпуса (`consoleColor`, он же цвет сложности
  в меню: «очень легко» — белый (Корзинка), «легко» — зелёный (Птичка), «сложно» — красный (Космос)).
  Ядро про яблоки, птиц и пришельцев не знает. Общие помощники квестов — `src/lessons/kit.ts`.
  Все игры перечислены в `src/lessons/index.ts` — из него строится главное меню.
- Конец игры: `lives <= 0` (Корзинка, Космос) или `gameOver === true` (Птичка). «Границы» рисует обвязка — своя функция
  на каждую игру (`HITBOXES` в `runtime.js`, id игры приходит в строке `__TB_CFG`).
- Адреса (`src/app/routes.ts`): без параметров — главное меню, `?game=<id>` — игра, `&finished` — готовая версия.
- `src/sandbox/runtime.js` — первый скрипт в iframe (обвязка). В нём нельзя писать закрывающий тег скрипта.
  Игра потеряла фокус — обвязка сама шлёт `keyup` на все зажатые клавиши.
- Игры рисуют не смайликами, а своими рисунками — пиксель-арт 24×24 клетки (на экране 34×34), имена по-русски.
  126 рисунков в девяти группах (Смайлы, Животные, Сказка, Еда, Сокровища, Вещи, Природа, Транспорт, Космос;
  группы «Герои» нет — по просьбе пользователя), каждая группа — свой файл `src/core/art/<группа>.ts`;
  набор и порядок групп — `src/core/pictures.ts`. Прежние имена (`колобок` → `улыбка`, `мышь` → `летучая мышь`)
  — в `PICTURE_ALIASES`: они остались в сохранениях учеников. Холст — `src/core/pixels.ts`: рисунок собирается
  из фигур (`circle`, `ellipse`, `poly`, `stroke`), `Px.fill` раскладывает их по клеткам с тенью, светлой каймой
  и контуром `INK`; мелочи — `stamp`/`dots`. По краю сетки — только контур (проверяет юнит-тест).
  Наружу рисунок уходит как SVG из прямоугольников (`pictureSvg`, `shape-rendering="crispEdges"`).
  В игре — готовая функция движка `drawPic("ракета", x, y)` (`DRAW_PIC` в `src/lessons/engine.ts`) поверх
  `picture(name, size)` из обвязки (растеризует SVG в холст и кэширует); адреса рисунков уходят в iframe
  строкой `__TB_PICS` (`src/sandbox/harness.ts`) — только те, чьи имена есть в коде ученика, и «?». В интерфейсе — `pictureUrl(name)` из ядра. Переменные с рисунками — `…Pic`: у них в редакторе кнопка
  «Сменить» с миниатюрой и окно выбора (`PickWindow`). В интерфейсе рисунок — компонент `Pic`.
- Все массивы и состояние игры — только в «Движке»: движок зовёт `loop()` раньше, чем выполнятся другие
  вкладки, и массив из вкладки ученика в первом кадре был бы `undefined`.
- Шапка игры сама сжимается, когда не помещается (`useSqueeze` в `Header.tsx`): без подписей → без текста
  «Сбросить всё» → в две строки. Ширину не угадывать брейкпоинтами — подписи у игр разной длины.
- Гайд начинается с карты игры (`Roadmap.tsx`): дорога со станциями — шаги (у каждого `pic` в `GuideStep`),
  бонусные задания и финиш; пройденная дорога жёлтая, текущая станция пульсирует, над ней пиксельная
  стрелка; станция пройдена — вспышка (`data-burst`) и переезд стрелки, только когда «Гайд» виден.
  Под картой — одна станция: выбранная (`station` в сторе, `showStation` в контроллере; выбор забывается,
  когда ученик ушёл дальше) или текущая; остальные блоки скрыты (`hidden`), но не размонтируются. Станции
  считает ядро — `stationList`/`hereStation` в `levels.ts`. На узком экране карта листается вбок.
  Финиш (`Finish` в `Guide.tsx`): открыт — герой ученика (`chosenPic` по `card.heroVar`) на пьедестале, полка
  пройденного и кнопки, тогда «Открыть готовую игру» внизу гайда скрыта; закрыт — что осталось, кнопками к станциям.
- `src/app/controller.ts` — вся логика приложения; React-компоненты тонкие и читают внешний стор.
- Загрузка (`src/main.tsx`): меню — лёгкий кусок (React, уроки), игра — отдельный `src/app/game.tsx` (редактор,
  acorn, обвязка) через `import()`; меню подгружает его заранее, когда браузер свободен. Пока игра грузится, в `#root`
  виден экран загрузки из `index.html` (кубик и дорожка, стили `boot-*` там же); не загрузилась — `Boot failed`.
  Редактор и acorn в меню не импортировать.
- `src/editor/` — CodeMirror: один EditorView, по EditorState на вкладку.

## Проверки перед коммитом

```bash
npm run lint
npm run build      # tsc -b + vite build
npm test           # vitest: ядро и логика игры без браузера
npm run test:e2e   # playwright: сайт в /hitbox/ (Chromium уже установлен в облачном окружении)
```

## Деплой

Репозиторий — `xrnskew/hitbox` (перенесён из `xrnskew/TimeBox` со всей историей). Веток ровно две
(просьба пользователя):

- `main` — высшая ветка, то, что на сайте. Пуш в неё выкладывает сайт.
- `dev` — рабочая. Работать всегда в `dev`, даже если сессия выдала ветку `claude/…`: её не пушить
  и не создавать на GitHub. После всех проверок — `git push origin dev`.
- `dev` → `main`, когда пользователь просит выложить: fast-forward `git push origin dev:main`
  (если `main` ушла вперёд — сначала влить `main` в `dev`). Других веток не заводить.
- `main` защищена (`docs/MAIN.md`): правила GitHub `.github/rulesets/main.json` пускают только коммит
  с зелёными «Проверками» (то есть уже из `dev`), без force-push и удаления; в сборке шаг «Коммит есть в dev».
  Пуш в `main` отклонён — дождаться зелёных проверок `dev` в Actions и повторить.

Хостинг — только GitHub Pages (Vercel убран), домен `hitbox.space` (куплен на reg.ru, DNS —
Yandex Cloud DNS, `docs/DOMAIN.md`).
`.github/workflows/pages.yml` на каждый пуш в `dev` и `main`: «Проверки» (линтер, сборка, юнит-тесты,
сквозные в Chromium) → «Сборка» (`BASE_PATH` от `actions/configure-pages`: на github.io — `/hitbox/`, на своём
домене — `/`) → «Выкладка» только для `main`. Красные проверки — сайт не меняется.
Вручную ничего не выкладывать без явной просьбы пользователя.

## Задачи в Notion

План и статусы — в Notion: страница «HitBox — состояние проекта»
(https://app.notion.com/p/3f3b2e3f46ad81739c03fa270e4c9aab), в ней база «Задачи HitBox»
(data source `collection://61229841-8f10-4bc5-adf8-e85e4e31cdd8`; поля «Задача», «Статус»: Сделано / В работе /
Доработать / Идея, «Область», «Приоритет», «Описание»). Просьба пользователя: вести её самому — взял задачу →
«В работе», сделал → «Сделано» (описание — что сделано), нашёл новое → новая карточка.

Там же база «Сессии» (data source `collection://333510d4-13e5-4d67-bee3-095f645f668a`; поля «Сессия» — кодовое
имя, «Дата», «Статус», «Итог», «Задачи» — связь с задачами). Когда пользователь закрывает сессию, он даёт ей кодовое
имя: создать запись (что сделано, коммиты, что на следующую сессию), связать с задачами сессии; добавить
в «Статус» задач вариант с кодом сессии (серый) и перевести в него все задачи из «Сделано» — колонка «Сделано»
пустеет к новой сессии; незаконченное — отдельной карточкой на следующую сессию. Вид «Сделано по сессиям»
группирует архив по сессиям. Первая сессия — A0S0B1 (8 октября 2026).
