# TimeBox

TimeBox — конструктор игр: ученик собирает код игры на JavaScript по квестам. Слева код по
вкладкам и гайд, справа игра. Игры:

- **Корзинка** (очень легко, адрес `?game=catch`): сверху падают яблоки, внизу ездит герой.
- **Птичка** (легко, как Flappy Bird, `?game=bird`): птица падает, пробел — взмах, навстречу едут трубы
  с дыркой. Новое — скорость: гравитация прибавляется к скорости, скорость — к высоте.
- **Космос** (сложно, `?game=space`): стрелялка — корабль внизу, пули, волны пришельцев зигзагом.
  Новое — второй массив, вложенный цикл (пуля × пришелец) и перезарядка.

Игры рисуют не смайликами, а своими рисунками: 53 картинки пиксель-арт 24×24 (`src/core/pictures.ts`).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Без параметров открывается главное меню с выбором игры и прогрессом по каждой; `?game=<id>` — сама игра.

`?game=<id>&finished` (для Корзинки — и просто `?finished`) — готовая версия игры со своим сохранением:
у Корзинки — бомба, звезда, +10 очков, ускорение; у Птички — монетки и ускорение труб; у Космоса —
взрывы и волны всё быстрее.
Она открывается по паролю учителя (в коде лежит только хеш; это защита от случайного
открытия, а не настоящая).

## Скрипты

| Команда                | Что делает                                                             |
| ---------------------- | ---------------------------------------------------------------------- |
| `npm run dev`          | дев-сервер Vite                                                        |
| `npm run build`        | проверка типов + сайт в `dist/` (GitHub Pages)                         |
| `npm run build:single` | один файл `dist-single/hitbox.html` для работы без интернета           |
| `npm test`             | юнит-тесты (Vitest): склейка, синтаксис, переводы, логика игры         |
| `npm run test:e2e`     | сквозные проверки (Playwright): файл через file:// и сайт в `/hitbox/` |
| `npm run check`        | линтер, сборка и юнит-тесты                                            |
| `npm run lint`         | линтер (oxlint)                                                        |
| `npm run preview`      | локальный просмотр собранного `dist/`                                  |

## Ветки

- `main` — то, что на сайте. Пуш в `main` выкладывает сайт на GitHub Pages — но только если прошли проверки.
- `dev` — рабочая ветка: все изменения сначала сюда, в `main` — когда пора выкладывать.

Каждый пуш в `dev` и `main` проверяет `.github/workflows/pages.yml`: линтер, типы и сборка, юнит-тесты,
сквозные проверки в Chromium и пробная сборка сайта. Красные проверки — сайт не меняется.

`main` защищена: в неё попадает только коммит, уже прошедший проверки в `dev`; force-push и удаление
запрещены (`docs/MAIN.md`, правила — `.github/rulesets/main.json`).

## Где открыть

- **Сайт** — https://hitbox.space (GitHub Pages; пока домен не подключён — https://xrnskew.github.io/hitbox/).
  Собирает `.github/workflows/pages.yml` при пуше в `main`. Путь сайта сборка узнаёт у Pages сама: на github.io
  это подпапка `/hitbox/`, на своём домене — корень `/` (локально тоже `/`). Как подключить свой домен
  с reg.ru — `docs/DOMAIN.md`.
- **Без интернета** — `dist-single/hitbox.html` (`npm run build:single`): один файл со всем
  внутри (код, стили, шрифты), открывается двойным кликом в Chrome с флешки, без сервера.
  Готовый файл есть и на сайте: https://hitbox.space/hitbox.html (сохранить как…), и в артефакте
  `hitbox` у каждого запуска workflow в Actions.

Роутинга нет: готовая игра — это тот же адрес с `?finished`, поэтому прямые ссылки и
обновление страницы на Pages не дают 404.

## Что умеет

- **Код по вкладкам** (у Корзинки «Движок → Герой → Яблоки → Поимка»), у каждой вкладки своя история отмены.
  «Движок» выдан готовым: в нём всё состояние игры и настройки.
- **Гайд начинается с карты игры:** дорога со станциями — шаги, бонусные задания и финиш. Под картой открыта
  одна станция — текущая или выбранная; пройдена станция — вспышка, и стрелка переезжает к следующей.
- **Шаг — цепочка квестов:** код собирается по кусочкам кнопкой «Добавить», которая всплывает прямо в коде
  вкладки; есть квесты «поправь сам» (скорость, своя картинка из окна выбора) и «нажми «Собрать»».
  Следующий шаг открывается, когда выполнены все квесты.
- **Бонусные задания** — после сборки игры: одна кнопка добавляет переменную в «Движок», вторая вставляет код.
- **«Собрать»** (Ctrl+Enter) склеивает вкладки и запускает игру; прогресс в шапке — галочки шагов и бонусов.
- **Ошибки** с вкладкой и строкой на понятном языке; синтаксис проверяется ещё во время печати.
- **Подсказки** к именам движка (автодополнение и при наведении мыши).
- **«Приборы»** (значения переменных), консоль для `console.log`, «Границы» — рамки столкновений.
- Стабильные 60 кадров на мониторах 120/144 Гц, чёткий холст на Retina.
- Сбросы с подтверждением и отменой, сохранение в браузере, рекорд.
- Игра живёт в карманной приставке своего цвета: кнопки на корпусе работают мышью и пальцем.

## Структура

```
src/
  main.tsx, App.tsx       точка входа и раскладка
  app/                    контроллер (вся логика) и маленький внешний стор
  core/                   чистые модули: склейка, синтаксис, переводы ошибок, прогресс,
                          уровни и станции карты, пароль готовой игры, рисунки
  lessons/index.ts        список игр — из него строится главное меню
  lessons/kit.ts          общие помощники квестов: куда вставить кусок, как проверить
  lessons/catch/          урок Корзинка: код вкладок, гайд, задания, подсказки
  lessons/bird/           урок Птичка — устроен так же
  lessons/space/          урок Космос — устроен так же
  sandbox/                обвязка iframe (runtime.js), сохранение
  editor/                 CodeMirror: вкладки, тема, подсказки, всплывающие куски кода
  components/             интерфейс
  styles/                 токены, база, общие примитивы
  assets/fonts/           Unbounded, Onest и JetBrains Mono (woff2, OFL)
tests/unit/               Vitest
tests/e2e/                Playwright
docs/SPEC.md              ТЗ
docs/PLAN.md              план и предложения; docs/PLAN-space.md — план Космоса
docs/DOMAIN.md            свой домен с reg.ru для GitHub Pages
```

Импорты из `src` можно писать через алиас `@/`, например `import App from '@/App'`.
Модули `src/core` импортируют друг друга относительными путями — их можно запускать в Node напрямую.
