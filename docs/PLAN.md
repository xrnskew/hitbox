# План: «Лови яблоки» v2 в проекте TimeBox

Песочница, где подросток по шагам пишет игру «Лови яблоки». Концепт остаётся прежним:
вкладки склеиваются в один скрипт, «Движок» выдан готовым, гайд ведёт по трём шагам,
есть бомба и звезда, сбросы обратимы. Меняются три вещи: архитектура (чистый проект на TS),
скорость и вес, интерфейс. Плюс несколько новых функций для урока.

> **Статус.** План выполнен. Решения пользователя: всё восстановить самостоятельно, TypeScript
> без Tailwind, взять все функции из раздела 4, деплой в новый Vercel-проект со сборкой из
> репозитория. Из P3 был сделан `playSound` (в версии 4 убран); второй урок — Птичка — сделан в версии 6.

## 1. Решения, которые нужно принять до старта

1. **TypeScript вместо JS.** Рекомендую TS: этого требует `CLAUDE.md`, и проект уже так настроен.
   Чистые модули (`runner`, `syntax`, `guide`, `tabs`) пишу без алиаса `@/` и только на стираемом
   синтаксисе (`erasableSyntaxOnly`). Тогда Node 22.18+ запускает их напрямую: `node -e "import('./src/sandbox/runner.ts')"`.
   Проверка через `node -e` из ТЗ продолжает работать.
2. **Без Tailwind.** Рекомендую обычный CSS с токенами (`:root { --color-… }`) и CSS-модулями.
   Тогда исчезают обе ловушки из ТЗ: `@theme static` и правило с `min()/calc()`, которое Tailwind
   не сгенерировал. Тема CodeMirror берёт `var(--color-…)` напрямую, без чтения из JS.
3. **TimeBox — платформа или одна игра?** Рекомендую так: ядро не знает про яблоки, а игра
   подключается как «пакет урока» (вкладки, гайд, ключ сохранения, подсказки к именам).
   Сейчас пакет один, но вторую игру можно будет добавить без переписывания.
4. **Деплой.** Куда выкладывать: в старый Vercel-проект `catch-sandbox` или в новый `timebox`?
   В любом случае только по явной просьбе, каждый раз заново.
5. **Какие новые функции брать в первую версию.** Список в разделе 4, моя рекомендация — блок P1.

Что меняется по сравнению со старой версией:

- **`runner.js` делится на четыре модуля**: склейка, синтаксис, переводы, вставка.
  Каждый маленький и проверяется отдельно.
- **Обвязка iframe лежит в файле**, а не в строке внутри JS. Место `FOCUS` — это отдельная строка
  `/*FOCUS*/`, её заменяют на `window.focus();` или на комментарий. Число строк не меняется.
- **Состояние не в `App`**, а во внешнем сторе. Печать в редакторе не перерисовывает React:
  статусы вкладок пересчитываются с задержкой (debounce) и обновляют только `TabBar` и шапку.
- **Пакет урока отделён от ядра** (см. решение 3).

Все механизмы из раздела 4 ТЗ переносятся без изменений: новый iframe на каждый запуск,
два скрипта в обвязке, `onerror` в первом, номер строки из `/srcdoc:(\d+)/`, проверка
`e.source`, фокус, карта строк по `runCodesRef`, проверка синтаксиса по вкладкам до запуска,
формат сообщений и переводы, сохранение (ключи, 400 мс, pagehide).

## 3. Оптимизация

1. **60 кадров на любом мониторе.** Сейчас движок сдвигает всё на фиксированное число пикселей
   за кадр. Поэтому на мониторе 120 Гц (MacBook Pro, игровые ноутбуки, многие телефоны) игра идёт
   в 2 раза быстрее, а на 144 Гц — в 2,4 раза. Исправлю в обвязке, текст движка не меняется:
   `requestAnimationFrame` внутри iframe оборачивается и вызывает колбэк не чаще 60 раз в секунду.
   Эта же обёртка даёт паузу, шаг по кадрам и замедление (раздел 4).
2. **Вес сборки.** Отдельные пакеты `@codemirror/*` вместо `codemirror` с `basicSetup`. Шрифты
   только в подмножествах latin и cyrillic: вариативный Onest — один файл на все начертания.
   Цель — меньше 450 КБ gzip для `dist/index.html` целиком. Измерю и запишу в README.
3. **Меньше перерисовок React.** Внешний стор с селекторами, `memo` на тяжёлых компонентах,
   у редактора и гайда стабильные колбэки. Гайд не размонтируется, а для его секций вне экрана
   стоит `content-visibility: auto`.
4. **Опрос состояния игры дешёвый.** Для «Приборов» и оверлея «Игра окончена» значения читаются
   из `contentWindow` 5 раз в секунду, только пока вкладка видима (`visibilitychange`).
5. **Проверки автоматизированы.** Vitest для чистых модулей и Playwright (Chromium уже стоит
   в окружении) для чек-листа из раздела 11 ТЗ. Зажатие клавиш — через CDP,
   офлайн — через `file://` и блокировку сети. Сейчас это делалось руками, теперь будет одной
   командой `npm test`.

## 5. Дизайн

ТЗ задаёт тёмную тему «в духе редактора кода» и точные токены. Их сохраняю. Ниже то, что
добавляется сверху, и то, что стоит поправить.

### 5.1. Палитра: что проверил

Посчитал контраст по WCAG (нужно 4.5:1 для обычного текста):

| Токен | На `ground` | На `raised` | Вывод |
| --- | --- | --- | --- |
| `ink` #dcdee3 | 13.6 | 10.4 | отлично |
| `dim` #9197a1 | 6.2 | 4.8 | годится для второстепенного текста |
| **`faint` #636873** | **3.3** | **2.5** | **для текста не годится.** Только для номеров строк и декора. Для подписей — новый `faint-text` #80858f (4.9 на `ground`) |
| **`comment` #6a9955** | 5.5 | **4.2** | на активной строке и подсветке (`raised`) не дотягивает. Предлагаю #72a35c (4.7) |
| `ok` / `danger` | 8.7 / 7.6 | 6.7 / 5.9 | контраст хороший, но см. ниже |

**Красный и зелёный почти одинаковой яркости** (относительная яркость 0.45 и 0.39). При
красно-зелёном дальтонизме (до 8 % мальчиков, то есть примерно один ученик на класс) их не различить.
Поэтому значки вкладок различаются **формой**, а не только цветом:
○ пусто · ● есть код · ✓ сделано · ▲ ошибка. В шапке сделанный шаг закрашен и с галочкой.

### 5.2. Шрифты

- **Интерфейс и гайд — Onest.** Сделан с кириллицей с самого начала, лицензия OFL, есть
  вариативная версия. Дружелюбный, но не детский. Не Inter и не системный шрифт.
- **Код — JetBrains Mono**, лигатуры выключены, как в ТЗ.
- Шкала: 13 / 15 / 17 / 21 / 28 px. Текст гайда 17 px, межстрочный 1.6, строка не шире 68 символов.
- Оба шрифта лежат внутри сборки, офлайн работает.

### 5.3. Один запоминающийся элемент — ветка с яблоками

Вместо трёх обычных плашек в шапке — тонкая ветка с тремя яблоками: «Герой», «Яблоки», «Поимка».
Шаг не сделан — контур яблока. Шаг сделан — яблоко зелёное (`ok`), закрашенное, с галочкой.
Зелёный цвет «сделано» из ТЗ сохраняется, и он же цвет спелого зелёного яблока. Учитель
видит прогресс с другого конца класса.

Это **единственное место с анимацией без действия пользователя**: когда шаг впервые засчитан,
яблоко один раз падает в корзинку-счётчик «2/3». Всё остальное спокойное. При
`prefers-reduced-motion` яблоко просто закрашивается.

### 5.4. Остальной интерфейс — тихо и аккуратно

- **Рамка игры как экран.** Без фокуса — затемнение и крупно «Кликни, чтобы играть». С фокусом
  затемнение пропадает, рамка светится `accent`. Строка-подсказка под игрой остаётся.
- **Гайд — сплошной документ, а не набор одинаковых карточек.** Шаги нумеруются, потому что это
  действительно последовательность. Задания на улучшение номеров не получают. Блок кода
  выглядит так же, как редактор: те же номера строк и цвета `tok-*`.
- **Ошибка** — как в ТЗ, плюс метка на полях редактора и волнистое подчёркивание.
- **Уведомления** — тонкая полоска обратного отсчёта, чтобы было видно, что оно скоро исчезнет.
- **Убираю типовые приёмы, которые выдают шаблон:** заголовок `🍎 Лови яблоки · песочница`
  становится «🍎 Лови яблоки» с маленькой меткой «песочница». Стрелки «→» не добавляются в каждую
  кнопку. Подписи без капса.
- **Тексты.** Кнопка называет действие: «Запустить», «Вставить во вкладку «Герой»»,
  «Вернуть как было». То же слово в уведомлении. Ошибка говорит, что случилось и что сделать.
- **Доступность.** Вкладки — `role="tablist"` с переключением стрелками. Видимый фокус
  у всех кнопок. Окна — нативный `<dialog>`. Нет горизонтальной прокрутки на 375 px.
