# Свой домен с reg.ru для GitHub Pages

Сейчас сайт работает по адресу https://xrnskew.github.io/hitbox/. После этих шагов он откроется на вашем
домене `https://hitbox.space`, а старый адрес будет сам перекидывать на новый.

В коде ничего менять не нужно: сборка (`.github/workflows/pages.yml`) сама узнаёт у Pages, где живёт сайт,
и на своём домене собирает его в корень `/`, а не в подпапку `/hitbox/`.

Домен — `hitbox.space` (куплен на reg.ru), подключаем его целиком: вариант 2а.

## 0. Выбрать адрес

- **Весь домен** (`hitbox.space` и `www.hitbox.space`) — шаги 2а.
- **Только поддомен** (например, `game.hitbox.space`, а сам `hitbox.space` занят чем-то другим) — шаги 2б.

## 1. Подтвердить домен в GitHub (защита от угона)

Без этого шага кто-нибудь другой может привязать ваш домен к своему Pages, если ваш сайт однажды отключится.

1. GitHub → аватарка справа вверху → **Settings** → слева **Pages** (раздел «Code, planning, and automation»).
2. **Add a domain** → ввести `hitbox.space` → **Add domain**.
3. GitHub покажет TXT-запись: имя вида `_github-pages-challenge-xrnskew` и значение — длинную строку.
   Страницу не закрывайте.
4. В reg.ru (как попасть в DNS — шаг 2, пункты 1–3) добавить запись **TXT**:
   - Subdomain: `_github-pages-challenge-xrnskew`
   - Text: строка из GitHub
5. Подождать 10–30 минут и нажать в GitHub **Verify**. Если не прошло — подождать ещё и нажать снова
   (у reg.ru записи иногда расходятся до нескольких часов).

## 2. DNS-записи в reg.ru

1. https://www.reg.ru → **Личный кабинет** → **Домены** → нажать на свой домен.
2. Вкладка **DNS-серверы и управление зоной**. В блоке «DNS-серверы» должно быть `ns1.reg.ru` и `ns2.reg.ru`.
   Если там другие — **Изменить** → **Бесплатные DNS-серверы Рег.ру** → **Готово** и подождать до суток,
   пока новые серверы заработают.
3. Ниже, в «Ресурсных записях», — **Изменить** / **Добавить запись**.

Быстрее начать с мастера reg.ru «Подключение домена к хостингу или сервису» → **Указать IP-адрес** →
`185.199.108.153` → **Подключить домен**. Мастер сам поставит серверы `ns1.reg.ru`/`ns2.reg.ru` и одну
A-запись. Остальные записи из 2а (ещё три A и CNAME `www`) потом добавить в «Ресурсных записях» вручную.

### 2а. Весь домен

**Сначала удалить** старые записи `A` и `AAAA` для `@` и все записи (`A`, `CNAME`) для `www` — reg.ru ставит
их по умолчанию на свою страницу-заглушку. Если их оставить, сайт будет открываться через раз.

Добавить четыре записи **A** (Subdomain `@`):

| Тип | Subdomain | Значение          |
| --- | --------- | ----------------- |
| A   | @         | `185.199.108.153` |
| A   | @         | `185.199.109.153` |
| A   | @         | `185.199.110.153` |
| A   | @         | `185.199.111.153` |

По желанию — ещё четыре **AAAA** (для IPv6), тоже `@`:
`2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`.

И одну **CNAME** для `www`:

| Тип   | Subdomain | Значение            |
| ----- | --------- | ------------------- |
| CNAME | www       | `xrnskew.github.io` |

### 2б. Только поддомен

Удалить старые записи для этого поддомена, если есть, и добавить одну:

| Тип   | Subdomain | Значение            |
| ----- | --------- | ------------------- |
| CNAME | game      | `xrnskew.github.io` |

(`game` — ваш поддомен. В конце значения не нужно писать `/hitbox` — только `xrnskew.github.io`.)

## 3. Указать домен в репозитории

1. https://github.com/xrnskew/hitbox → **Settings** → слева **Pages**.
2. **Build and deployment → Source** должно быть **GitHub Actions** (уже так).
3. **Custom domain** → ввести `hitbox.space` (или `www.hitbox.space`, или `game.hitbox.space`) → **Save**.
4. GitHub проверит DNS — появится зелёное «DNS check successful». Если красное — записи ещё не разошлись,
   подождать час и нажать **Check again**.
5. Когда появится галочка **Enforce HTTPS** — поставить её. Сертификат выпускается сам, от 15 минут
   до суток; пока его нет, галочка серая.
6. Чтобы сайт пересобрался уже под корень `/`: **Actions** → **GitHub Pages** → **Run workflow** → `main`.
   (Или просто дождаться следующего пуша в `main`.)

Файл `CNAME` в репозиторий класть не нужно — при выкладке через GitHub Actions домен хранится в настройках.

## 4. Проверить

- `https://hitbox.space` открывает главное меню, игры запускаются.
- `https://www.hitbox.space` перекидывает на `https://hitbox.space` (для варианта 2а).
- `https://xrnskew.github.io/hitbox/` перекидывает на новый домен.
- `https://hitbox.space/hitbox.html` — офлайн-версия одним файлом.

## Если что-то не так

| Что видно                                   | Что делать                                                                        |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| Страница-заглушка reg.ru                    | Остались старые A-записи `@` или `www` — удалить их (шаг 2а).                     |
| 404 от GitHub                               | В Settings → Pages не сохранён Custom domain или сайт ещё не пересобран (3.6).    |
| Белый экран, в консоли 404 на `/hitbox/...` | Сайт собран под старый адрес — Run workflow (3.6).                                |
| «Domain is improperly configured»           | DNS ещё не разошёлся — подождать до суток; проверить на https://dnschecker.org    |
| Enforce HTTPS не включается                 | Подождать; если есть записи CAA — разрешить в них `letsencrypt.org`.              |
| Домен `.рф`                                 | В GitHub вводить в punycode (`xn--...`); reg.ru показывает его в карточке домена. |
